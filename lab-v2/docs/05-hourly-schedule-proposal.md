# 시간당 관리 예약 — 검토용 제안 (미생성)

## 중복 확인 [실제]
- 이 Claude 계정의 예약: **0건**(완료·비활성 포함 조회, 2026-11-10).
- 기존 연구소 예약은 **ChatGPT 쪽**(매일 01·07·13·19시 연구, 08시 보고)이며 이 제안과 다른 시스템이다. 이 시험은 기존 원장·예약을 읽거나 바꾸지 않으므로 기존 예약과 겹쳐 실행돼도 서로 간섭하지 않는다.

## 목적
사용자 맥(MacBook·iMac)이 꺼져 있고 이 대화 세션도 쉬는 동안에, **클라우드에서 스스로 시작한 실행**이 실제 출처를 수집하고 결과를 영속 저장하는지 확인한다(무인·맥 종료 시험).

## 매 실행이 하는 일 (새 세션, Sonnet)
1. `rate_limit_info`를 확인한다. `limited`이면 아무 작업 없이 `waiting_limit` 한 줄만 기록하고 종료.
2. 시험 작업 1건: `collectors/law_go_kr.py`로 「개인정보 보호법」 제34조, `collectors/riss.py`로 '침해사고 신고' 서지 후보 수를 조회.
3. 결과(시각·세션ID·상태·조문 해시·후보 수·오류)를 `lab-v2/runs/log.jsonl`에 한 줄 추가하고 이 작업 브랜치에 커밋·푸시.
   - 원장 결정 전이므로 Notion에는 쓰지 않는다(무인 쓰기 승인 문제 회피). 기록 내용은 공개 법령 조문 해시와 공개 서지 수뿐이라 lab-v2 상시 푸시 승인 범위 안이다. 원고·개인정보·인증정보는 다루지 않는다.
4. 그 외 작업(연구원 생성, 다른 저장소·서비스 변경)은 하지 않는다.

시험 후 확인: 맥을 끈 시간대의 커밋 시각·세션 ID가 연속으로 남았는지, 빠진 시각이 있는지 대조.

## 구독 사용량과 과금
- 실행 경로: claude.ai 구독 로그인 세션. API 키·유료 API를 쓰지 않는다.
- 사용량: 매 실행이 구독의 사용량 창(현재 메타데이터상 5시간 창)을 소모한다. 1회 규모는 작업자 E 수준(짧은 Sonnet 세션)으로 예상하나 **잔량은 조회할 수 없어 추정하지 않는다.**
- 추가 과금 가능성: 이 세션 경로에는 유료 API 결제가 없다. 다만 claude.ai 계정의 **추가 사용량(overage) 설정**은 내가 확인할 수 없다. 현재 하위 세션 메타데이터는 `isUsingOverage=false`. 시험 전에 claude.ai 설정에서 추가 사용량이 꺼져 있는지 확인을 권장한다. 매 실행은 `isUsingOverage=true`를 보면 즉시 중단하고 예약을 끈다.

## 중지 조건
- 기간: 생성 후 **24시간 또는 24회** 중 먼저 도달 시 스스로 비활성화(`update_trigger enabled=false`).
- 연속 2회 실패(푸시 실패·수집 오류) → 비활성화하고 원인 기록.
- `isUsingOverage=true` 감지 → 즉시 비활성화.
- 사용자는 언제든 "예약 중지"라고 하면 내가 삭제한다(앱의 예약 목록에서도 직접 중지 가능).

## 생성 시 설정값
- 이름: `연구소v2 무인시험 (24h)`
- 주기: 매시 1회(서버가 생성 시각 기준으로 분산 고정), 매번 새 세션
- 모델: Sonnet / 환경: `web1 연구소 v2`(공식 출처 19개 도메인 허용)
- 커넥터: 없음(빈 목록) — Notion·Gmail 등 사용 안 함
- 알림: 기본값(푸시만), 이메일 끔
