# 실제 연구소 ↔ 생활관 캐릭터 연동 설계 (구상, 2026-11-11)

목표: 지피가 지시함에 쓴 지시를 연구소가 백그라운드에서 처리하고, 그 **실제 진행 상태**를 생활관(홈페이지) 캐릭터가 따라 움직인다.
원칙: 실제 상태가 없을 때 일하는 척하지 않는다(생활 장면은 '연출'로 구분). 공개 화면에는 허용 목록 값만. 키·원고·개인정보는 브라우저로 가지 않는다.

## 1. 전체 흐름
```
지피 ──(Notion 연구 지시함에 행 작성)──▶ 지시함
                                         │  매시 :12 관리자 예약(Claude, 구독 사용량)
                                         ▼
                          관리자 실행: 잠금 → 지시 읽기 → OpenAI 연구원 사슬(수집→초안→검토→수정)
                                         │  단계가 바뀔 때마다
                                         ├─▶ 비공개 원장(gx999/daeyong-lab): 전체 기록(원문·초안·비용)  ── 지피가 읽음
                                         └─▶ 공개 상태 파일 status.json(허용 목록만)                    ── 홈페이지가 읽음
                                                                                     │ 30~60초마다
                                                                                     ▼
                                                           생활관 화면: 캐릭터가 실제 단계에 맞춰 움직임
```

## 2. 지시 → 처리 시작까지 걸리는 시간
| 방식 | 시작 지연 | 비용·조건 |
|---|---|---|
| 지금(매시 1회 예약) | 최대 60분 | 구독 사용량, 추가 승인 없음 |
| 예약 2개(:12, :42) | 최대 30분 | 구독 사용량 약 2배. 할 일 없으면 1분 내 종료 |
| 사용자 '지금 실행'(예약 화면 Run now) | 1분 내 | 사용자가 직접 누름 |
| GitHub 이슈·API 호출로 즉시 시작 | 1분 내 | 지피가 이슈를 쓰거나 API를 부를 수 있어야 함 — 현재 지피는 GitHub 읽기만 확인됨[미확인] |
권장: 우선 매시(현행) + 급할 때 사용자 Run now. 사용 패턴을 본 뒤 2개 예약 여부 결정.

## 3. 처리 중 상태를 '실시간에 가깝게' 보이기
- 관리자 실행 한 번 안에서 사슬 전체가 약 2분에 끝난다(T24-1 실측). 단계마다 공개 상태를 갱신하면 화면에서 수집→초안→검토→수정이 순서대로 보인다.
- 각 단계 사건에 `at`(실제 시각)을 넣고, 화면은 늦게 받아도 **사건 순서대로 재생**한다(받은 시각과 실제 시각을 함께 표시).
- 관리자 매시 점검(잠금 기록) = 지피 순찰 장면으로 표현. 마지막 확인이 90분 넘게 끊기면 '연결 확인 중' 표지판(일하는 척 금지).

## 4. 공개 상태 형식 — 홈페이지 v1 계약(`PublicLabState`)을 그대로 사용
v1 `lab-types.ts` 형식(agents/projects/events/reports)으로 내면 홈페이지의 기존 해석 코드를 재사용할 수 있다.
```json
{ "mode": "live", "revision": 42, "serverTime": "…", "sourceObservedAt": "…(원장 관측 시각)",
  "execution": { "enabled": true, "reason": "" },
  "lab": { "name": "정대용 디지털 연구소", "status": "running", "paused": false },
  "agents": [ { "id": "research", "name": "미나", "role": "자료 조사", "state": "researching",
               "summary": "공식 법령 원문 수집", "taskId": "T24-1", "observedAt": "…" } ],
  "projects": [ { "id": "T24-1", "title": "(공개 제목 또는 '비공개 과제')", "status": "running", "priority": 3, "updatedAt": "…" } ],
  "events": [ { "id": "…", "agentId": "research", "type": "handoff", "toAgentId": "writer", "summary": "원문 전달", "at": "…" } ],
  "reports": [] }
```
포함하지 않음: 원고·초안 본문, 출처 원문, 프롬프트, Notion 내용, 세션 ID, 모델 이름, 비용, 실패 원문. 지시 제목은 지시함 '공개 가능' 표시가 있을 때만, 없으면 '비공개 과제'.
시험 지시(test=true)는 '시험' 표시를 붙여 공개하거나 제외(결정 필요).

## 5. 단계 → 캐릭터 대응
| 원장 상태 | 담당 | 생활관 장면 |
|---|---|---|
| 지시 접수(accepted) | 지피 | 현황판 앞에 서서 지시 확인, 💡 |
| 수집(collect) 진행 | 미나 | 자료실 책장 → 읽기 동작, 초록 말풍선 '실제 기록' |
| 수집 일부 실패(transient/access) | 미나 | 💧 + "원문 일부 미확보(보류)" |
| 초안(draft) | 솔 | 자기 책상, 모니터 초록빛 깜빡임, 타이핑 |
| 인계(handoff) | 보낸 사람 → 받는 사람 | 종이 들고 걸어가 건네기 |
| 독립 검토(review) | 클로 | 회의 구석에서 읽기 → 판정 말풍선(approve/revise) |
| 수정(revise) | 솔 | 책상 타이핑, 지적 수만큼 체크 표시 |
| 완료(done) | 모두 | 하이파이브·반짝, 현황판 갱신 |
| 막힘(blocked) | 담당 + 지피 | ?, 지피가 찾아와 회의 |
| 사용량 한도 대기(waiting_limit) | 담당 | 라운지 휴식, '한도 대기' 표지 |
| 사용자 검토 대기(waiting_user) | 지피 | 우편함/알림 아이콘, "검토 기다리는 중" |
| 야근(퇴근 시각 이후 진행) | 담당 | 책상 스탠드 + 동료 간식 배달 |
| 실험·계산(향후) | 코디 | 실험 책상 |
실제 진행 중인 캐릭터는 생활 연출보다 우선한다. 진행이 없으면 생활 연출로 돌아간다.

## 6. 공개 상태 파일을 어디에 둘 것인가
| 안 | 내용 | 장점 | 필요한 승인 |
|---|---|---|---|
| A. 새 공개 저장소(권장) | `status.json` 한 파일만 있는 공개 GitHub 저장소. 관리자 실행이 단계마다 푸시. 화면은 raw 주소로 읽음 | 무료, 지금 구조에 바로 붙음, 내용이 허용 목록뿐 | 공개 저장소 생성·공개 범위, 예약에 저장소 추가 |
| B. 기존 v1 공개 상태 서버(*.chatgpt.site) | 지피의 공개 게시 도구로 올림 | 기존 홈페이지 그대로 | 기존 서비스 변경, 지피 실행 주기(1시간 이상)라 단계별 표시 어려움 |
| C. 홈페이지(Firebase) 정적 파일 | 배포 때마다 갱신 | 한 곳에 모임 | 배포 권한, 실시간성 낮음 |

## 7. 보안·정확성 장치
- 공개 변환은 `kernel/projection.py`의 허용 목록 + `assert_public_safe` + 개인정보 정규식 검사 통과 시에만 푸시.
- 공개 저장소에는 `status.json`(최신)과 `history/`(최근 50개 사건)만. 비공개 원장과 섞지 않음.
- 화면은 `revision`이 줄어들거나 `serverTime`이 미래면 무시. 90분 이상 갱신 없으면 '연결 확인 중'.
- 브라우저에는 키·토큰 없음(공개 파일 읽기만).
