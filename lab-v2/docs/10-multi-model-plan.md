**권장: ②.** 비공개 GitHub 원장이 영속 상태, 과제·이벤트(이슈 생성, 연구원 완료 호출)가 생길 때만 독립 실행자가 생성된다. ①과의 차이: 상주 프로세스가 없고, 시작마다 세션 기동 지연·시간당 시작 상한이 있으며, 문맥은 메모리가 아니라 원장으로 이어진다.

## 5. OpenAI 첫 24시간 시험 예산 제안 (실제 한도는 사용자 결정)
- 프로젝트 강제 지출 한도: **$5** (반영 지연 감안)
- 프로그램 내부 예산: **$3** — 응답의 사용 토큰 × 공식 요금표(시험 전 사용자와 확인)로 누적, 도달 즉시 OpenAI 호출 중단
- 요청별: 출력 토큰 상한, 시간 상한, 재시도 1회, 동시 2, 하루 호출 수 상한, 웹 검색 호출 수 상한
- 즉시 중단 조건: `credit_balance_exhausted`·`insufficient_quota`·결제 관련 오류 → 재시도 없이 OpenAI 연구원 정지, Claude 연구원은 계속
- 예상 비용: 모델·요금 확인 전이라 **금액을 만들지 않는다**. 시험 첫 호출 1건의 실제 사용량으로 단가를 산정해 보고 후 진행
- 위험 소진 상황(잔액 소진·한도 초과)은 모의 오류로 시험

## 6. 사용자 결정·권한과 구현 순서
1. **Claude 사용 크레딧 꺼짐** 확인 (claude.ai/settings/usage)
2. **OpenAI 대시보드 확인**: 크레딧이 있는 조직·프로젝트 이름, 잔액·만료, 결제수단 없음 또는 자동충전 꺼짐, 유료 잔액 0, 프로젝트 강제 한도 설정
3. **OpenAI API 키**: 해당 프로젝트 전용 키를 만들어 보안 입력 양식으로 저장(프록시가 주입, 채팅·코드·로그에 노출 안 됨) — 새 인증정보 승인
4. 관리자 예약 생성(24시간, 종료 장치 3중) 승인 + 비공개 저장소 이슈 트리거(웹 화면에서 사용자 설정)
5. (선택) Jules 접근 확인
구현 순서: 비용 장치 코드(내부 예산·중단) → OpenAI 검토자 어댑터(모의) → 관리자 예약 → 24시간 시험 → 결과 보고.
