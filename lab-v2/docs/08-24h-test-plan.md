# 24시간 1차 무인 시험 계획 (생성 전 — 추가 사용량 꺼짐 사용자 확인 대기)

## 시작 조건 (모두 충족해야 예약 생성)
1. ✅ 사용자가 claude.ai 설정에서 **사용 크레딧(usage credits)·추가 사용량 꺼짐**을 직접 확인함(2026-11-10, 사용자 진술). Claude 세션은 이 설정을 읽을 수 없어 사용자 확인에 근거. (Claude 세션은 계정 설정을 읽을 도구가 없음 — 실행 기록의 `isUsingOverage=false`는 설정 증거가 아님)
2. 유료 API 키·결제 경로 없음(현재: API 키 미보유, 구독 로그인 세션만).
3. 기존 연구소(ChatGPT 예약·아침 보고·Sites 서버)는 읽지도 바꾸지도 않음.

## 예약 설정 (생성 시)
- 이름 `연구소v2 24시간 무인시험`, 매시 1회, 매번 새 세션, 모델 Sonnet, 환경 `web1 연구소 v2`, 커넥터: Notion(지시함 **읽기**만 — 쓰기 시도 금지), 알림 push.
- **종료 장치 3중:** ① 매 실행이 `ops/schedule.json`의 `end_at`을 보고 지났으면 자기 예약을 `enabled=false` ② 별도 1회 예약(end_at+5분)이 시험 예약을 끔 ③ 사용자 언제든 "예약 중지".
- 생성 직후 `get_trigger`로 다음 실행 시각·활성·프롬프트를 재조회해 기록. 끝난 뒤 다시 조회해 `enabled=false` 확인.

## 매 실행 순서 (`tools/manager_run.py`)
1. `get_session`(자기)로 `rate_limit_info` 확인 → `isUsingOverage=true`면 **즉시 예약 끔·중단·알림**. `limited`면 '사용량 한도 대기' 기록 후 종료(유료 전환 없음).
2. 비공개 저장소 pull → `plan-observe` → 실행 중 세션 `get_session`, 키 미연결 실행은 `list_sessions(tags)`로 조회 → obs.json.
3. Notion 「연구 지시함」 읽기(쓰기 없음) → 규칙 처리.
4. `tick`: 연구원 결과 수집 → **확인된 종료만** 재배정(unknown은 재배정 안 함) → 다음 단계 생성.
5. `to_launch`마다 `create_session`(source=daeyong-lab, tags=[실행키, 'lab-v2-test'], Sonnet) → `adopt`.
6. `summary --push`.

## 시험 과제 (모두 `test=true`, 기존 연구소 과제와 다른 ID·주제)
- **T24A** (정상 경로): 「정보통신망법 제48조의4(침해사고 원인분석)·제48조의2와 개인정보 보호법 안전성 확보조치의 침해사고 자료 보전 관련 조문 비교」 — 수집→초안(≤800자)→별도 세션 검토→수정 연결 확인.
- **T24B** (실패 격리): 수집 대상에 대법원 사이트(접근 거부 확인됨)만 지정 → `blocked`가 되어도 T24A가 계속 진행되는지.
- 동시 실행 상한 2. 수정 상한 3. 원고는 비공개 저장소에만.

## 맥 종료 확인
사용자가 맥을 끈 시각·켠 시각을 알려 주면, 그 사이 `ledger/events`의 `manager_run` 기록(세션 ID·시각)을 대조한다. 알려 주지 않으면 '맥 종료 상태 미확인'으로 보고한다.

## 홈페이지 연동 (이번 시험에서 실행하지 않음)
- 비공개 저장소를 직접 연결하지 않는다. 관리자 실행이 `kernel/projection.py` 허용 목록 투영(역할 별칭·상태 열거값·생성 시각만, 시험 과제 제외)을 만들어 **별도 공개 상태 파일/서버**로 전달하는 구조.
- 후보: (a) 기존 공개 상태 서버(`*.chatgpt.site`)에 지피의 `lab_publish_public_projection`으로 게시 — 기존 서비스 변경·승인 필요 (b) 홈페이지 저장소에 정적 `status.json` 커밋·배포 — Firebase 배포 권한 필요 (c) 새 공개 상태 엔드포인트 — 호스팅 승인 필요.
- 필요한 권한·검증 결과는 시험 후 별도 보고.
