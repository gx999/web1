# 연구 지시 → 백그라운드 연구 → 생활관 연동 → 지피 보고 (운영 절차 초안, 2026-11-11)

## 흐름
```
사용자 ─(요청)─▶ 지피 ─(Notion 연구 지시함에 행 작성)─▶ 지시함
                                                    │ 매시 :12 관리자 예약(Claude 구독 사용량)
                                                    ▼
  잠금 → 공개 상태 게시(지피 점검 장면) → 지시 읽기 → OpenAI 연구원 사슬(수집→초안→독립 검토→수정)
       │ 단계마다                               │ 완료 시
       ├─▶ 공개 상태 status.json(허용 목록)      └─▶ 비공개 보고서 reports/<지시ID>.md + status/reports.json
       │     └─ GitHub Pages → daeyongjeong.com/lab/life/ 캐릭터(약 20~30초 지연)
       └─▶ 비공개 원장 gx999/daeyong-lab(전체 기록)
                                                    ▼
  지피: status/reports.json 에서 미보고 항목 확인 → 보고서를 파일(DOCX/PDF 등)로 사용자에게 보고
       → 지시함에 '종류=report_done, 대상=<지시ID>' 행 작성 → 다음 매시 실행이 '보고 완료' 표시 → 생활관 지피 인사 장면
```

## 지피가 쓰는 지시 행(Notion 연구 지시함)
| 열 | 연구 지시 | 보고 완료 표시 |
|---|---|---|
| 요청ID | 고유값(예: R-2026-11-12-1). 중복이면 거절 | 고유값(예: R-2026-11-12-1-보고) |
| 종류 | `new_task` | `report_done` (선택 항목 추가 필요) |
| 대상 | `openai_chain` | 보고한 지시ID(예: R-2026-11-12-1) |
| 내용 | 첫 줄: 연구 질문 / 둘째 줄: `조문: 법령명 제N조; 법령명 제M조` (최대 `max_articles`개) | 비워도 됨 |
| 시험 | 체크 안 함(운영) | 체크 안 함 |
- 접수 뒤 내용을 고치면 다시 실행하지 않음(새 행 필요). 원고·개인정보·내부자료를 내용에 넣지 않음.

## 지피가 읽는 곳(비공개 저장소 gx999/daeyong-lab, 읽기 전용)
- `status/reports.json`: `reported_by_gippy`가 null이면 아직 보고 안 한 결과.
- `reports/<지시ID>.md`: 보고서(지시 내용, 결과물, 독립 검토 의견, 근거 원문 표, 처리 기록, 확인 필요 사항).
- `status/directives/<지시ID>.json`: 접수·거절·진행·완료 이력(거절 사유 포함).
- 보고서는 '검토 전 초안'이며 공개·투고·외부 전송은 사용자 승인 후.

## 걸리는 시간
- 지시 작성 → 처리 시작: 최대 약 60분(매시 :12, 실제 0~7분 늦게 시작). 급하면 사용자가 예약 화면에서 '지금 실행'.
- 처리: 약 2분(T24-1 실측). 생활관 반영은 단계마다 약 20~30초 뒤.
- 보고: 지피가 status/reports.json을 확인하는 주기에 따름(지피 쪽 설정).

## 운영 전환에 필요한 결정·승인(24시간 시험 종료 후)
1. 운영 게이트(ops/openai_gate.json 교체): 기간, 총액·일일 호출 상한, 시험 지시만 허용 해제.
2. 예약 지시문 교체(trigger_prompts.md E절) + 예약 저장소에 `gx999/daeyong-lab-status` 추가(사용자 화면).
3. Notion 지시함 '종류'에 `report_done` 선택 항목 추가(지피).
4. 지피의 보고 확인 주기와 보고 형식(DOCX/PDF/Notion 페이지).

## 운영 보정 (2026-11-12, 첫 실제 연구 G-20261112-AML-02 뒤)
- 공개 상태 푸시 묶기: 단계 중 게시는 직전 게시 후 25초가 지나야 푸시(`PUBLISH_MIN_INTERVAL`), 그 사이 변경은 다음 게시에 합쳐짐. 실행 마지막 게시는 항상 반영. 원인: 몇 초 간격 6회 푸시 → Pages 배포 취소·대기 → 마지막 판이 약 5분 늦게 보임(실측 14:16:50 → 14:22).
- 위험어 검사 범위: `openai_chain` 연구 지시는 첫 줄(무엇을 하라는지)에만 공개·결제·인증·권한 등 위험어 검사. 본문의 연구 대상 설명은 검사하지 않음(AML-01 '인증 의무화' 오탐). 첫 줄의 행동 요청은 여전히 사용자 승인 필요.
